## 0. Java とは何か？

*** 用語: Java（ジャバ） ***

~~~
1995年に Sun Microsystems（現在は Oracle に吸収合併済）が開発したプログラミング言語。

世界で最も広く使われている言語の一つで、
Android ・企業の基幹システム・銀行ATM・組み込み機器などの
幅広い分野で採用されている。
~~~

---
### 0-1. Java の立ち位置

Java が使われている身近な例

```
  📱 Android アプリ    … スマホアプリの旧開発言語（現在は Kotlin）
  🏦 銀行・金融システム … ATM・勘定系システムの多くが Java 製
  🏢 企業の基幹システム … 在庫管理・販売管理・ERP など大規模業務システム
  🖥 デスクトップアプリ  … 今回の JavaFX アプリがこれに該当
  ☁ クラウド / Web API … Spring Boot フレームワークで Web サービス
```

---
### 0-2. プログラミング言語の「種類」から見た Java の特徴

プログラミング言語はいくつかの「分類」で整理できます。

- インタプリタ言語（逐次実行型）

書いたコードをその場でその場で1行ずつ読みながら動かす

→ 変更がすぐ反映される。実行が始まるまでが早い

例: JavaScript / PHP / Python / Ruby

- コンパイラ言語（事前変換型）

実行前に「全コードを機械語に変換（コンパイル）」してから動かす。

→ 大規模・複雑なシステムに向いている

例: Java / C / C++ / Go / Rust

---
## 料理で例えると…

- インタプリタ（JS/PHP）: 「レシピを見ながらその場で調理する」

→ すぐ作り始められるけど、途中で失敗してから気づく

- コンパイラ（Java）: 「調理前に材料・手順の不備を全部チェックする」

→ 実行前に問題が判明する、大人数分の調理（大人数・大規模システム）に向いている

---
### 0-3. Java の 3 大特徴

1. 型がある（静的型付け言語）

JavaScript:
~~~
let price = 100;     // 型は後から何でも入れられる
price = "100円";     // ← これでも動いてしまう！
~~~

Java:
~~~
int price = 100;    // 「整数型」と決めたら
price = "100円";    // ← コンパイル時にエラー！
                    // 型の不一致を実行前に発見できる  │
~~~

---
### 0-3. Java の 3 大特徴

2. どこでも動く（Write Once, Run Anywhere）

Java でビルド（コンパイル）したプログラムは Windows でも Mac でも Linux でも同じファイルで動作する。

→ JVM（仮想マシン）が OS の差を吸収してくれるおかげ

---
### 0-3. Java の 3 大特徴

3. オブジェクト指向（クラスとオブジェクト）

JavaScript でもオブジェクト指向でプログラムを書けるが、Java はすべてがオブジェクト単位

プログラム全体が「部品（クラス）の組み合わせ」で構成される

→ 大規模チーム開発・長期保守に強い

### 1-3. Web vs Java ── 考え方の違い 一覧

| 比較項目 | Web アプリ (HTML/PHP) | Java デスクトップアプリ |
|---|---|---|
| **実行の入口** | ブラウザで URL を開く | `java -jar ファイル名.jar` コマンド |

| **動かすまでの手順** | ファイルをサーバーに置くだけ | **コンパイル** ➔ **ビルド** ➔ 実行（3ステップ） |

| **DB 接続方法** | PHP の PDO | Java の JDBC |
| **エラーの確認** | ブラウザの開発者ツール | ターミナルのエラーメッセージ |

## 2. Java を動かすための「3 つの道具」

Java でデスクトップアプリを作るには、３種類のソフトウェアが必要です。

料理に例えると…
```
┌──────────────────────────────────────────────────────────────┐
│                    Java アプリを作る「料理」                   │
│                                                              │
│  🔥 コンロ (熱源)          →  JDK (Java Development Kit)      │
│     Java プログラムを                                         │
│     「コンパイル＆実行」する基盤                                │
│                                                              │
│  📦 宅配便の箱 (まとめ役)   →  Maven (ビルドツール)             │
│     必要な材料（ライブラリ）を                                  │
│     自動で集めて、1つの実行ファイルに梱包する                     │
│                                                              │
│  🍽 盛り付け皿 (見た目)     →  JavaFX SDK (GUI フレームワーク)   │
│     ボタン・入力欄・テーブルなど                                │
│     デスクトップ画面の「部品」を提供する                         │
└──────────────────────────────────────────────────────────────┘
```

### 2-1. JDK（ジェイディーケー）

*** 用語: JDK (Java Development Kit) ***

Java でプログラムを「コンパイルする・実行する」ための開発用キット（道具セット）。

- javac コマンド … ソースコード (.java) を機械語に変換（コンパイル）する
- java コマンド  … 変換済みプログラムを実行する

| Web 開発での対応 | Java での役割 |
|---|---|
| Node.js の実行環境 | JDK の実行環境（JRE） |
| npm の `node` コマンド | `java` コマンド |
| ── | `javac` コマンド（コンパイル。JSには存在しない概念）|

---
### 2-2. Maven（メイヴン）

*** 用語: Maven ***

Java のプロジェクト管理・ビルド自動化ツール。

`pom.xml` という設定ファイルに「使いたいライブラリ名」を書いておくだけで、
インターネットからライブラリを自動ダウンロードして、実行ファイル (.jar) を作ってくれる。

---
**JavaScript の npm との比較:**

```
┌─────────────────────────────────────────────────────┐
│  JavaScript (npm)          │  Java (Maven)          │
│  ─────────────────────     │  ──────────────────    │
│  package.json              │  pom.xml               │
│    "dependencies": {       │    <dependencies>      │
│      "axios": "^1.0"       │      <artifactId>      │
│    }                       │        javafx-controls │
│                            │      </artifactId>     │
│  npm install  → 自動DL      │  mvn package → 自動DL  │
│  node_modules/ に保存       │  ~/.m2/ に保存          │
└─────────────────────────────────────────────────────┘
```
▲ 考え方はほぼ同じ！ npm ≒ Maven

### 3-2. ① package と import ── JavaScript との比較

```java
// ─── ① このファイルの「住所」宣言 ───────────────────────────
package com.example.lesson13;
//  JS でいう: src/example/lesson13/ フォルダに置いてある、というイメージ

// ─── ② 使う「部品」を予め宣言する ──────────────────────────
```

** 💡 <b>JavaScript との比較ポイント **

JavaScript:

~~~
import { Button } from 'javafx-controls';
~~~

Java:

~~~
import javafx.scene.control.Button;
~~~

「使いたいものは先に宣言する」という考え方は JavaScript の import と全く同じ！

Java では **クラス名（部品名）まで正確に書く** ルールがある。
`*` （アスタリスク）で「このフォルダの全部品を一括取込」も可能。

### 3-3. ③ start() ── 画面の組み立て

HTML/JavaScript/PHP では HTML タグをテキストで書きますが、Java では **コードで部品を作って並べます。**

```
┌──────────────────────────────────────────────────────────────┐
│  HTML の書き方                │  Java (JavaFX) の書き方        │
│──────────────────────────────│───────────────────────────────│
│  <div style="display:flex;   │  VBox mainLayout = new VBox();│
│    flex-direction:column">   │                               │
│    <h1>タイトル</h1>          │  Label title =                │
│    <input type="text">       │    new Label("タイトル");      │
│    <button>検索</button>     │  TextField input =            │
│    <table>...</table>        │    new TextField();           │
│  </div>                      │  Button btn =                 │
│                              │    new Button("検索");        │
│  ↑ テキストで構造を「書く」     │  TableView table =            │
│                              │    new TableView();           │
│                              │  mainLayout.getChildren()     │
│                              │    .addAll(title,input,btn,   │
│                              │            table);            │
│                              │  ↑ コードで部品を「組み立てる」  │
└──────────────────────────────────────────────────────────────┘
```

---
**ボタンのクリックイベントの比較：**

```
JavaScript:
  document.getElementById('btn').addEventListener('click', performSearch);

Java:
  searchButton.setOnAction(e -> performSearch());
```

** 💡 <b>ポイント **

`e -> performSearch()` は JS の arrow 関数 `(e) => performSearch()` と全く同じ考え方！

「ボタンが押されたら `performSearch()` を呼ぶ」という意味です。

### 3-4. ④ performSearch() ── DB 検索の流れ

performSearch() の処理の流れ
```
  ① 入力欄から売上番号を取得（文字列）
      ↓
  ② 数字かどうかチェック（数字でなければエラーポップアップ）
      ↓
  ③ MySQL に JDBC 接続
  │   ┌──────────────────────────────────────────────────┐
  │   │ PHP の書き方:                                     │
  │   │   $pdo = new PDO("mysql:host=10.8.0.1", $u, $p); │
  │   │                                                  │
  │   │ Java の書き方:                                    │
  │   │   Connection conn =                              │
  │   │     DriverManager.getConnection(url, user, pass);│
  │   └──────────────────────────────────────────────────┘
      ↓
  ④ SQL を安全に実行（売上ヘッダー情報の取得）
  │   ┌──────────────────────────────────────────────────┐
  │   │ PHP:  $stmt = $pdo->prepare("SELECT ... WHERE    │
  │   │         tsh_sales_no = ?");                      │
  │   │        $stmt->execute([$salesNo]);               │
  │   │                                                  │
  │   │ Java: PreparedStatement ps =                     │
  │   │         conn.prepareStatement("SELECT ...");     │
  │   │        ps.setInt(1, salesNo);                    │
  │   │        ResultSet rs = ps.executeQuery();         │
  │   └──────────────────────────────────────────────────┘
      ↓
  ⑤ 結果を1行ずつ読み取り → TableView に追加
  │   ┌──────────────────────────────────────────────────┐
  │   │ PHP:  while ($row = $stmt->fetch()) {            │
  │   │         $row['mcu_name'];                        │
  │   │        }                                         │
  │   │                                                  │
  │   │ Java: while (rs.next()) {                        │
  │   │         rs.getString("mcu_name");                │
  │   │        }                                         │
  │   └──────────────────────────────────────────────────┘
      ↓
  ⑥ 画面（TableView）が自動的に更新される
```

---
*** 💡 <b>SQL 文自体は Python とまったく同じ！ ***

`SELECT` / `LEFT JOIN` / `WHERE` / `ORDER BY` の書き方はそのまま使えます。

変わるのは「SQL を送り込む方法（PDO → JDBC）」だけです。

## 4. 【ハンズオン】ビルド ➔ 起動 ➔ 動作確認

### 4-1. ビルド（コンパイル）とは何か？

*** 用語: ビルド (Build) ***

「ソースコード (.java ファイル) を実行できる形 (.jar ファイル) に変換する」一連の作業のこと。

料理でいえば「材料を集めて → 調理して → 完成品（弁当）に詰める」全工程。

---
```
ビルドの 3 ステップ（Maven が全自動でやってくれる！）

  ┌──────────────┐    ┌───────────────┐    ┌──────────────────────┐
  │ ① コンパイル  │ ➔ │ ② 依存解 決    │ ➔  │ ③ パッケージング      │
  │              │    │               │    │                      │
  │ .java ファイル│    │ JavaFX / MySQL│    │ すべてをまとめて       │
  │  を機械語に   │    │ ライブラリを    │    │ 1つの .jar ファイルに │
  │  変換する     │    │ 自動ダウンロード│    │ 梱包する (Fat JAR)    │
  └──────────────┘    └───────────────┘    └──────────────────────┘
   javac コマンド      Maven が処理         maven-shade-plugin
```

---
*** 用語: Fat JAR (ファット・ジャー) ***

必要なライブラリをすべて 1 つのファイルに詰め込んだ実行ファイル（.jar）のこと。

「太った（Fat）＝中身が詰まった jar」という意味。

配布が **1 ファイルをコピーするだけ** で完了するメリットがある。

---

### 4-2. ビルド手順

コマンドプロンプトを開き、以下を実行します。

## 5. ビルドの全体像を整理する

### 5-1. Web アプリ vs Java アプリ ── 動かすまでの流れ比較

```
【Web アプリ（Python）を動かすまで】

  ① .py / .html ファイルを作成
        ↓
  ② Apache サーバーの所定フォルダに置く
        ↓
  ③ ブラウザで URL を開く → 即実行！

  ✅ 手順が少なく、変更がすぐ反映される
  ❌ Web サーバーが必要、配布が複数ファイルになる
```

---
```
【Java アプリ（JavaFX）を動かすまで】

  ① .java ファイルを作成（今回は作成済み）
        ↓
  ② コンパイル: .java → .class（機械語に変換）
        ↓        Maven が自動でやってくれる
  ③ パッケージング: .class + ライブラリ → .jar（Fat JAR）
        ↓
  ④ java -jar ファイル名.jar で実行！

  ✅ 1ファイル（.jar）で配布・実行できる
  ✅ Web サーバー不要
  ❌ 変更のたびにビルドが必要
```

### 5-3. コンパイルとは何か？（JS との最大の違い）

*** 用語: コンパイル (Compile) ***

人間が書いたソースコードを、コンピュータが直接実行できる形式（機械語・バイトコード）に「事前変換」する作業のこと。

この変換作業を行うプログラムを「コンパイラ」と呼ぶ。

```
JavaScript（インタプリタ言語）:
  ソースコード (.js) ──────────────────────────▶ 実行
                         ブラウザ/Node.js が
                         その場でリアルタイム解釈

Java（コンパイラ言語）:
  ソースコード (.java)  ──▶  バイトコード (.class)  ──▶  実行
                    javac が事前変換              JVM が実行

  ┌──────────────────────────────────────────────────┐
  │ JS のメリット: ファイルを変更したら即反映できる       │
  │ Java のメリット: 実行前にエラーを全部発見してくれる    │
  │   例) 「この変数は存在しません」→ 実行前に気づける！   │
  └──────────────────────────────────────────────────┘
```

---
*** 用語: JVM (Java Virtual Machine) ***

Java のバイトコード (.class) を実行する「仮想マシン」。

Windows / Mac / Linux など OS の違いを吸収し、 *** どの OS でも同じ .jar ファイルが動く *** のはこの JVM のおかげ。

（"Write once, run anywhere" ── １回書けばどこでも動く）

```
┌─────────────────────────────────────────────────────────┐
│  ① Java アプリは「ビルド」してから動かす                    │

│  ③ Maven が「npm」の役割をしてくれる                       │
│     pom.xml に書くだけでライブラリを自動取得                │
│     build.bat 1 本で「コンパイル + 梱包」まで全自動         │
└─────────────────────────────────────────────────────────┘
```

### 6-4. 【補足】今後 Java をもっと学ぶなら

本レッスンは「Java を体験する」ことが目的でした。  <br>
もし今後 Java を本格的に学びたい場合は、以下のキーワードで調べてみてください：

- **オブジェクト指向（OOP）** ── `class` / `extends` / `interface` の考え方
- **型システム** ── `int` / `String` / `boolean` など静的型付け
- **例外処理（Exception）** ── `try / catch / finally` の詳細な使い方
- **Stream API** ── Java でのリスト・配列の高度な処理（JS の `map` / `filter` に相当）
